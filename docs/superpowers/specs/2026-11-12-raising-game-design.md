# 펫 키우기 게임 설계 (2026-11-12)

## 1. 목적

현실에서 동물을 키우지 못하는 사람이 웹에서 3D 펫 한 마리를 입양해 돌보고 교감하는 게임.
성공 기준은 "들어와서 밥만 주고 나가는" 것이 아니라 **머물게 되는 것**이다.
펫은 방치하면 죽고, 잘 키워도 수명이 다하면 죽는다.

## 3. 구조

- **프런트**: Vite + TypeScript + Three.js. 프레임워크 없음. UI는 캔버스 위 HTML/CSS.
- **배포**: GitHub `main` → Vercel 자동 배포.
- **데이터**: Supabase (`https://slcmpnknanrnfbzglrav.supabase.co`), Postgres + Auth + RLS.
- **서버 코드**: Vercel 함수 1개 `api/recover.ts`. service-role 키는 이 함수의 환경변수에만 둔다.

### 모듈

| 모듈 | 책임 | 의존 |
|---|---|---|
| `sim/` | 스탯 감소, 질병, 성장, 사망 판정. 순수 함수, Three.js·네트워크 모름 | 없음 |
| `scene/` | 방/공원 씬, 펫 모델 로딩, 애니메이션, 카메라, 낮/밤 조명 | three |
| `pet/` | 펫의 자율 행동(돌아다니기, 졸기, 시선)과 터치 반응 | `scene`, `sim` 상태 |
| `ui/` | 로그인, 입양, HUD, 행동 버튼, 일기, 추모 앨범 | DOM |
| `data/` | Supabase 호출(인증, 펫 저장/불러오기, 일기) | supabase-js |
| `audio/` | 효과음, BGM, 음소거 | Web Audio |

`sim`만 게임 규칙을 안다. 나머지는 `sim`의 상태를 보여주거나 저장할 뿐이다.

## 4. 인증과 복구키

- ID: 영문 소문자·숫자·`_`, 4~20자. 비밀번호: 8자 이상. 그 외 정보는 받지 않는다.
- 가입은 서버 함수 `api/signup`이 처리한다. 계정을 만들고(메일 확인 없이 바로 활성화) 120비트 난수 복구키를
  생성해 SHA-256 해시만 저장한 뒤, 원문을 **한 번만** 돌려준다. Supabase의 "Confirm email" 설정은 바꿀 필요가 없다.
- 화면은 복구키를 한 번 보여주고, "적어 두었어요"를 체크해야 다음으로 넘어간다.
- 복구: ID + 복구키 + 새 비밀번호 → `api/recover` → 해시 비교 → 비밀번호 변경 → 새 복구키 발급·반환.
- 시도 제한: ID당 5회 틀리면 15분 잠금. 실패 응답은 ID 존재 여부와 잠금 여부를 드러내지 않는다.

## 5. 데이터 모델

```
accounts  user_id PK(auth.users), username UNIQUE, key_hash, failed_attempts, locked_until
pets      id PK, user_id, species, name, born_at, died_at, death_cause, state jsonb, updated_at
diary     id PK, user_id, pet_id, kind, body, created_at
```

- `accounts`는 RLS를 켜고 정책을 두지 않는다. 서버 함수(service-role)만 읽고 쓴다.
- `pets`, `diary`는 본인 행만 읽기/쓰기.
- 살아있는 펫은 사용자당 1마리(`died_at IS NULL` 부분 유니크 인덱스).
- 스탯·수명·성격 카운트는 모두 `pets.state`에 들어 있다.
- 서버 시각은 RPC `server_now()`로 받아 기기 시계가 틀려도 게임 시간이 어긋나지 않게 한다.
  다만 상태 자체를 브라우저가 계산해 저장하므로, 작정하고 조작하는 것은 막지 못한다(11절 참고).
- 저장 실패에 대비해 브라우저에 사본을 두되, 서버의 `updated_at`보다 새로울 때만 쓴다(여러 기기 사용 대비).

## 6. 시뮬레이션

스탯(0~100): 포만감, 청결, 즐거움, 체력, 건강, 애정도.

- 깨어 있을 때 포만감은 약 10시간, 청결은 약 16시간, 즐거움은 약 12시간에 100→0.
- 포만감 또는 청결이 0이면 건강이 약 48시간에 100→0. 건강 0 = 사망(방치). 합쳐서 약 3일.
- 포만감·청결이 30 미만이면 시간당 확률로 발병(배탈/감기). 아프면 건강 감소가 빨라지고
  행동이 느려진다. 병원에 가면 치료되고, 치료하지 않으면 사망(질병)으로 이어진다.
- 성장: 아기 0~3일, 어린이 3~8일, 어른 8~24일, 노년 24일~. `lifespan_days` 도달 시 사망(노환).
- 성격: 돌봄 행동 누적 비율로 결정(쓰다듬기 많음 → 응석쟁이, 놀이 많음 → 장난꾸러기 등).
- 접속 시 `server_now() - last_tick_at`만큼 10분 단위로 따라잡기 계산을 한다.
  접속 중에는 1분마다 계산하고 변경 시 저장한다.

## 7. 플레이

**항상 켜져 있는 것**
- 펫이 방 안을 스스로 돌아다니고, 기분이 좋으면 춤추고, 필요한 게 있으면 사람을 보며 말풍선으로 알린다.
- 드래그로 쓰다듬기, 톡 누르면 깡충 뛰기, 바닥을 누르면 그쪽으로 달려온다.
- 현실 시각에 맞춘 낮/밤 조명. 밤에는 침대에서 잔다.

**돌봄 행동**
| 행동 | 방식 | 효과 |
|---|---|---|
| 밥 주기 | 사료를 골라 그릇에 드래그 | 포만감↑ |
| 놀이 | 공을 스와이프로 던지면 물어옴 | 즐거움↑, 체력↓ |
| 산책 | 공원 씬으로 이동, 탭한 곳으로 함께 걸음 | 즐거움↑, 건강↑, 청결↓ |
| 목욕 | 문질러 거품 내고 헹구기 | 청결↑ |
| 재우기 | 불 끄기 | 체력↑ |
| 병원 | 화면 전환 후 결과 안내(별도 병원 씬 없음) | 질병 치료 |
| 치우기 | 배변·말썽 흔적을 탭해 치움 | 청결↑ |

**돌발 상황**: 배탈, 감기, 쓰레기통 뒤집기, 배변.

**추억 일기**: 입양, 첫 산책, 첫 병원, 성장 단계 변화, 100번째 쓰다듬기 등을 자동 기록.
사망 시 일기와 함께 추모 앨범에 남는다.

**애니메이션 한계 대응**: 팩에 먹기·잠자기·아픔 클립이 없으면 기본 클립에
코드 모션(고개 숙이기, 웅크리기, 떨기), 소품(그릇, 공, 침대), 표정 이모트, 효과음을 조합한다.

## 8. 화면

- 캔버스가 뷰포트 전체. 스크롤 없음, 주소창·당김 새로고침 억제, PWA 전체화면 메타.
- 좌상단: 이름·나이, 상태 아이콘(수치 바 대신 표정. 탭하면 상세).
- 하단: 원형 행동 버튼 6개. 손으로 그린 느낌의 SVG 아이콘.
- 우상단: 일기, 음소거, 설정.
- 파스텔 단색, 둥근 한글 폰트. 그라디언트·유리 효과·이모지 아이콘·카드형 패널은 쓰지 않는다.

## 9. 오류 처리

- 저장 실패: 로컬에 보관하고 재시도, 화면에 작은 "저장 안 됨" 표시. 진행은 막지 않는다.
- 모델 로딩 실패: 재시도 버튼이 있는 안내 화면.
- 세션 만료: 로그인 화면으로 보내되 마지막 상태는 이미 저장되어 있다.

## 10. 테스트

- `sim/`: Vitest 단위 테스트(감소 속도, 3일 방치 사망, 밤 감속, 발병, 수명 사망, 따라잡기).
- `api/recover`: 올바른 키, 틀린 키, 잠금, 없는 ID 응답 동일성.
- 화면: 모바일·PC 뷰포트에서 실제 실행해 확인.

## 11. 범위 밖 (이후)

방 꾸미기, 옷, 코인 상점, 친구 방문, 랭킹, 여러 마리 사육, 다국어, 푸시 알림.

게임 규칙은 클라이언트에서 계산한다. 랭킹·재화가 없어 조작 이득이 없기 때문이며,
그런 기능을 넣을 때는 규칙 계산을 서버(RPC)로 옮겨야 한다.

## 12. 사용자가 해 줄 일

1. `supabase/schema.sql`을 대시보드 SQL Editor에서 실행.
2. Vercel 대시보드에서 `insanezindol/raising-game` 저장소 Import.
3. Vercel 환경변수 등록: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`.

## 13. 처음 설계에서 빠진 것

창밖 보기, 포인터를 눈으로 따라오기, 부위별 쓰다듬기 반응, 밤에 낑낑대기, 별도 병원 씬.
